# 提示词与模型约束说明

## 一、提示词的作用

平台提示词不是让模型自由回答实验问题，而是把模型限制在教师已配置的实验、课程知识图谱和程序计算结果内。提示词版本、图谱版本、实验配置和量规快照会随诊疗保存，便于教师复核和后续追溯。

2026-09-22 模板版本为 `v2.1-lesson-aligned`。本次依据实际教案和实验源程序补充：先区分T0/T1并核对初始化与重装寄存器是否配对；串口区分原始字节、HEX/文本显示及字符编码；例程注释的波特率和零误差延时不得替代实测依据。详细来源与差异见 `pilot-validation.md`。这些是模型生成约束，仍需教师复核，不能保证模型每次均正确识别错误。

当前模板版本由 `src/lib/prompt.ts` 管理。模型服务由 `src/lib/llm-provider.ts` 管理，平台当前可切换千帆、星火和 GLM。密钥只从环境变量读取，不进入提示词、数据库或导出材料。

## 二、提示词组成

每次模型请求由四部分组成：

1. **系统角色和边界**：说明模型是课程实验排障助手，不能代替教师、编译器或硬件测量。
2. **知识约束**：列出本次检索到的节点、节点名称、章节、易错点和真实先修边；模型不能使用列表外的课程结论。
3. **实验配置与程序计算**：提供教师确认的芯片、晶振、分频、模式、目标和允许误差。可计算的定时初值或波特率由程序生成，模型只能解释，不能自行改算。
4. **学生输入和结构要求**：提供脱敏后的现象、编号代码、代码行数，并要求按固定JSON结构返回分类、检查点、补链任务、复核说明和分项评价。

## 三、核心约束

### 1. 范围约束

输入必须首先命中三类支持故障之一。课程外问题，例如“午餐推荐”，直接拒绝，不调用模型。代码中的偶然关键词不能覆盖学生明确描述的实验现象；若现象和所选实验冲突，接口拒绝提交。

### 2. 图谱约束

模型只能引用注入的知识点编号。先修关系来自图谱真实边，平台禁止按节点排列顺序自动连线。教师回填的易错点必须属于本次相关节点，去重后按数量上限注入。

### 3. 数值约束

模型不得自行计算初值、波特率或计数次数。只有程序计算状态为 `ready` 时，提示词才提供数值；参数不完整、芯片不支持、时间口径不明确或误差超限时，只允许输出定性排查和缺失参数。

示例：

`0.05 × 11059200 ÷ 12 = 46080`

`65536 − 46080 = 19456 = 0x4C00`

这类计算由 `src/lib/calculations.ts` 完成，模型只能说明“应由教师按配置复核”。

### 4. 输出约束

返回内容必须包含：

```json
{
  "classification": "故障归类",
  "checkpoints": [
    {"point_id": "知识点编号", "instruction": "检查动作和观察标准"}
  ],
  "bridging_task": "下一步验证任务",
  "review_notes": ["需要教师复核的事项"],
  "assessments": [
    {
      "criterion_id": "量规编号",
      "score": null,
      "reason": "评分依据或缺失证据",
      "point_id": "知识点编号",
      "line_no": 1,
      "issue_type": "问题类型"
    }
  ]
}
```

检查器会拒绝以下输出：

- JSON结构不完整；
- 检查点引用未注入的知识点；
- 给出完整主程序替代排查任务；
- 混入 STM32/HAL 等其他芯片体系；
- 引用未经程序计算的寄存器值、波特率或计数次数；
- 分项分数超过教师量规上限；
- 代码行号超出学生提交范围；
- 把没有编译或硬件证据的代码写成“运行正确”。

## 四、教师复核规则

模型输出永远先进入待复核状态。教师应按以下顺序处理：

1. 检查故障归类是否与学生现象一致；
2. 对照实验配置、程序计算和代码行号；
3. 删除越界建议，补充可执行的观察标准；
4. 调整三级任务和分项评价；
5. 保存复核稿；
6. 确认发布。

保存和发布都带版本号。旧版本回执不能提交到新版本；同一版本的并发修改会被拒绝并要求刷新。学生只能读取已发布版本，不能读取模型原稿和教师未开放的任务正文。

## 五、模型故障和重试

单次模型请求最长40秒，总生成预算90秒，最多尝试两次。模型返回429、超时、鉴权错误或结构校验失败时，诊疗不会丢失，也不会重复创建；记录转为“待教师处理”。超过4个并发生成请求时，新提交先持久化并转人工，不调用模型。

## 六、数据和隐私边界

模型只接收脱敏后的现象和代码。平台会检测姓名自述、英文署名、学号、手机号、邮箱等常见身份信息，并在页面提醒学生删除；晶振频率、目标时间和寄存器值等技术数字保留。脱敏命中记录只保存规则和次数，不保存原始身份值。

真实课堂使用前，教师和学院仍需确认模型供应商、数据处理区域、部署位置和内容审查形式。模型样例、演示记录和接口测试不能作为真实课堂效果证据。

## 七、如何做提示词验收

建议使用四组反例进行验收：

| 反例 | 预期结果 |
|---|---|
| “午餐推荐” | 不调用模型，返回课程外问题提示 |
| 11.0592 MHz、12T、50ms | 只使用程序计算的 `0x4C00`，不能出现 `0x3CB0` 或 `0x4CB0` |
| `STM32 HAL_TIM_Base_Start_IT` | 拒绝跨芯片术语 |
| “我叫张三，学号A202401001” | 页面提醒删除，提交按钮禁用；技术频率数字仍保留 |

模型真实调用应使用脱敏的合成技术样例，并把供应商、模型、耗时、错误和解析结果记录到独立测试文件；不得读取或发送历史学生记录。
