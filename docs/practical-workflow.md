# 调试到求助的操作闭环

本轮聚焦八项实验中“运行什么、看什么、把什么交给教师”的操作衔接。修改位于独立分支；合并代码、重建和重启服务后才会影响线上页面。

## 本轮已实现

| 操作断点 | 改进后的行为 |
| --- | --- |
| 学生不知道从哪一个运行步长开始 | 按当前实验与程序版本给出起步步数和观察对象，提供“按提示推进”按钮。提示以原示例为前提，不自动判定学生修改后的程序正确。 |
| 按 INT0 后仍在看按键前的结果 | 显示“按键尚未执行”，提供继续执行 25 条的入口，执行前暂停记录导出与求助带入。 |
| 修改源码后旧结果仍可当作新结果下载 | 标注“上一版”，暂停 HEX、调试记录和求助带入；重新编译后恢复。向服务器重新编译失败时，不保留为可用结果。 |
| 改了采样下拉框后，分不清现有波形对应哪组条件 | 本次结果显示实际使用的晶振和采样范围；下拉框只改变下一次运行。导出取生成结果时保存的条件。 |
| 求助需要手工复制代码和读数 | 将本次代码与运行摘要带入表单，保留学生已写的现象；若表单已有不同代码，先确认是否替换。学生仍须填写实际问题并自行提交。 |
| 实验过程难以留存 | 下载当前 `.asm` 源码和 `.json` 调试记录；后者含完整源码、HEX、规范化源码摘要、工具链名称、时钟、步数、按键位置、寄存器、RAM 和采样点。 |

求助摘要明确标为“学生提交，待教师复核”，与现象一起通过原有服务端身份、脱敏、幂等和教师审核流程。它不是签名凭证，也不会自动形成验证通过或完成事件。超过 8,000 字符的源码不会被静默截断；现象和记录合计超过 2,000 字符时须精简或移除记录。修改求助表单中的代码会移除附带摘要，避免代码与结果错配。

## 用实验四验收

1. 用测试学习卡打开实验四，展开“真实汇编与虚拟调试”。
2. 编译并加载，按提示执行 20 条完成初始化，记录 P1 与 RAM 30H。
3. 按一次 P3.2。此时页面应提示输入尚未执行，下载记录和带入求助应不可用。
4. 执行按键后 25 条，再核对计数；默认原示例应从 0 变为 1。修改后的代码以实际仿真读数为准。
5. 下载调试记录，核对源码、晶振、步数及 `keySteps` 与该次运行一致。只修改采样范围但不运行时，下载内容仍须保留旧的实际采样条件。
6. 写下实际问题，再点“带入代码与记录，向教师求助”；检查现象未被替换、代码对应本次运行、摘要明确为仿真记录。提交后由教师在原始提交中核对。
7. 回到调试器修改源码，旧结果应标明上一版且不可导出；重新编译后再观察。切换预设前若改过代码，页面应提醒先保存源码。

历史分组灯 `S22.asm` 第一段延时较长：参考指令内核逐条核对首次从 AAH 变成 55H 的位置为第 1,114,138 条，未超过 200 万条上限。页面提示先执行 20 条观察初值，再按 50 万条累计推进。该核对描述程序路径，不代替本班板卡测试。

## 还需继续推进的实操问题

1. **同单复测入口。** 当前提交后进入诊疗页，调试器位于新建求助前的实验指导中。后续应允许在同一诊疗单内继续运行、提交前后记录，并与教师复核版本关联。
2. **草稿恢复。** 当前代码编辑仍在页面内存中；刷新、离开实验会丢失未保存内容，本轮提供源码下载。下一轮可建立按学习主体、实验和程序版本隔离的草稿恢复，并验证共用电脑退出后的隔离。
3. **实物验证。** 逐实验固定本班板卡、芯片、晶振、接线照片、观察量和合格条件，尤其是实验八驱动器与电机匹配。仿真采样不能作为电机转速、声音或完整电气波形的实测证据。
4. **课堂试用。** 先以小组试用记录首次成功运行耗时、有效求助所需补问次数和教师处理耗时，再决定扩大覆盖。当前没有采集这三项真实课堂基线，不能承诺改善比例。
