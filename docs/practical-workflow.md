# 学生实验台：从开始实验到求助

本轮按学生的实际顺序整理入口、运行、观察、留存与求助。代码位于独立 PR；合并、重建并重启服务后才会影响线上页面。

## 学生现在怎样使用

1. 进入课堂，选择教师安排的实验，点击“开始实验”或“继续实验”。有保存记录时，刷新可回到上次实验；明确的实验链接优先。
2. 点“运行程序”，自动编译并按该实验的起步步数执行。已有结果时点“继续观察”。每个实验都有简短的观察提示。
3. 修改源码后再点“运行程序”，更新读数。程序版本、单步、晶振、采样范围及寄存器细节收在进阶区域，按需展开。
4. 实验四的虚拟按键会直接执行后续 25 条指令并更新计数，无需再寻找运行按钮。请求失败时保留上次成功结果，不记录一次未成功执行的按键。
5. 代码及程序版本、晶振、采样设置自动保存在当前浏览器，按课堂、学生和实验隔离。切换实验或刷新后可恢复，恢复后必须重新运行才能得到结果。退出课堂会清除此学生的草稿，跨设备使用或退出前请下载源码。
6. 遇到问题，点击“带入代码与记录，向教师求助”，补充自己看到的现象后提交。尚未提交的现象、求助代码、所选问题方向、附带摘要及重试标识按学生与实验保存；切换实验或刷新可以恢复。可下载求助草稿；提交成功且读取到诊疗单后清除该实验的求助草稿。求助页可“返回实验”，刷新后仍可“查看上次求助”。

实验准备、课程原理与验证要求可展开阅读，首页保留明确的“实物接线与准备”入口。操作实物前仍须核对本班器材与接线。

## 记录与恢复的边界

- 保存编辑器与尚未提交的求助输入，不保存登录凭据或把旧运行结果恢复为有效仿真结果。求助中的已有摘要仍标注“学生提交，待教师复核”。存储失败时可下载源码和求助草稿；存在未保存的求助内容时，切换实验会先提醒。
- 每个实验保留一份当前草稿。切换程序版本会替换这份草稿；若源码有修改，会先提醒下载并确认替换。
- 修改源码后旧结果标为“上一版”，暂停 HEX、调试记录和求助带入；重新编译后恢复。编译失败不会让旧结果成为新代码的证据。
- 调整采样范围只影响下一次运行，现有记录保留生成结果时的实际条件。
- 可下载 `.asm` 源码及 `.json` 调试记录。记录包括源码、HEX、工具链、时钟、步数、按键、寄存器、RAM 和采样点。
- 带入求助会保留学生现象；表单已有不同代码时先确认替换。摘要明确标为“学生提交，待教师复核”，经原有身份、脱敏、幂等及教师审核流程提交。
- 超过 8,000 字符的源码不会被静默截断；现象和记录合计超过 2,000 字符时需精简或移除记录。改动求助表单代码会移除附带摘要。

上述行为不自动判定程序正确、实验完成或实物验证通过。

## 浏览器验收步骤

1. 用测试学习卡首次打开实验四，点击“开始实验”，应能直接看到代码、“运行程序”与观察提示；进阶调试默认收起。
2. 点“运行程序”，默认示例初始化至 20 条。按一次虚拟 P3.2，执行至 45 条，核对 RAM 30H 与 P1 默认从 0 变为 1。连续按键每次只增加一次；请求失败可重试。
3. 修改一行代码，切到实验五，再回实验四，检查修改仍在；刷新后仍可恢复。恢复页面没有旧的有效运行结果。
4. 改晶振或程序版本后重跑，下载记录，核对源码、运行条件与结果一致。仅改采样范围、不运行时，下载记录仍是原来的实际条件。
5. 写下问题，再带入本次代码与记录，检查原有现象保留、代码匹配，由学生自行提交。提交后返回实验，代码应仍在；可以回到上次求助。
6. 先下载源码，再退出课堂；同一学生重新加入不应恢复已清除的草稿，另一学习卡不得读到该学生草稿。关闭浏览器存储权限时应显示下载提示。
7. 分别以 390 / 768 / 1440px 视口检查按钮、代码、观察区域与展开内容，并用键盘检查入口及焦点。

历史分组灯 `S22.asm` 的首次交替在参考内核第 1,114,138 条发生：先执行 20 条看初值，“继续观察”每次推进 50 万条。其他实验沿用各自起步步数。此核对不代替本班板卡测试。
