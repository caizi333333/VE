# 虚拟工程师 · 课堂试用版

《微控制器原理及应用技术》的实验辅导平台。学生首页以原始报告的八个实验为主线，每项按课程知识、实验准备、编写与运行、观察与验证的顺序组织，再在遇到问题时向教师求助；查看下一实验不代表完成。另有 **中断不触发、串口乱码、定时不准** 三类模型辅助诊疗专题；模型生成教师初稿，学生只接收教师批准的版本。现有六件可独立打开的交互式原理课件，供相关实验补充观察中断、定时、串口、端口、扫描和控制时序；课件仍需任课教师核对后用于正式教学。

**在线体验：**[学生实验台](https://ve.sunyancai.top/) · [教师工作台](https://ve.sunyancai.top/teacher)。登录需要教师创建的账号或演示学习卡；仓库不提供任何真实凭据。实验八所附普中-6图示来自《普中51单片机开发攻略 V1.2》，仅供对应板型核对，不表示本班采用该板型。

## 启动

配套材料： [平台使用说明](docs/platform-user-guide.md) · [项目要求与证据对照表](docs/project-deliverables-map.md) · [提示词与模型约束说明](docs/prompt-specification.md) · [课堂试用验证记录](docs/pilot-validation.md)

需要 Node.js 22 或更高版本，并安装 SQLite 命令行工具。依赖版本固定在 `package-lock.json`，按锁文件安装。

```bash
npm ci
cp .env.example .env.local
npm run db:migrate
npm run teacher:create
npm run dev
```

访问 `http://localhost:3100`；教师入口为 `/teacher`。`teacher:create` 默认创建 `teacher`，随机密码只写入 `tmp/teacher-access-teacher.txt`（仅当前系统用户可读）。已有账号不会覆盖。可用 `npm run teacher:create -- --username teacher2 --name 任课教师` 指定新账号；可用 `TEACHER_INITIAL_PASSWORD` 环境变量指定初始密码，要求 12–256 字符。不要把密码放进源码或共享报告。

生产运行：

```bash
npm run build
npm start
```

数据库由 `DATABASE_URL` 指定，默认 `prisma/dev.db`。本轮按**单个 Node.js 实例、本地 SQLite 文件**设计；登录频率限制在进程内。部署到多实例前需要共享限流、集中会话管理和数据库适配，不能仅替换连接串。正式部署应配置 HTTPS，并设置 `SECURE_COOKIES=true`。

## 远程试用入口

当前账号的远程入口为 [ve.sunyancai.top](https://ve.sunyancai.top/)，教师入口为 [ve.sunyancai.top/teacher](https://ve.sunyancai.top/teacher)。源代码同步到公开仓库 [caizi333333/VE](https://github.com/caizi333333/VE)。Cloudflare Tunnel 将 HTTPS 请求转发到本机仅监听 `127.0.0.1:3110` 的生产实例；用户登录后仍由平台在服务端校验教师、学习卡及班级归属。macOS 登录时的 `com.sunyancai.ve-app` 和 `com.sunyancai.ve-tunnel` 启动项维持服务，配置位于当前用户的 `~/Library/LaunchAgents/`。更新代码后须先重新构建，再重启应用启动项；本地数据库和 `.env.local` 不在 GitHub 仓库内。

这是**通过 Cloudflare 域名访问本机服务的远程试用**，不是把数据库和后端迁移到 Cloudflare Workers。电脑关机、睡眠或离线时网站不可用；第二个 Cloudflare 账号目前未在本机登录，尚无第二处部署。进入真实课堂前，还需核对实验设备、资料发布状态、备份与学校网络及数据要求。

## 开课和试用

1. 教师登录，建立班级。真实课堂选择“课堂”；演示选择“演示”。填写学院要求的内容审查记录编号或说明。
2. 发放匿名学习卡。学生凭**班级码＋匿名编号＋私密恢复码**加入；恢复码仅发给对应学生。班级码、编号、诊疗单号都不能单独读取个人记录。教师可停用学习卡或更换班级码。
3. 在“实验资料”按班级和实验上传图片、PDF、DOCX 或 PPTX，核对后再发布。上传件默认未发布，学生只能查看本班对应实验的已发布件。八实验原始空白报告已随平台保存，供登录师生下载。
4. 新建专项诊疗实验时，确认芯片、晶振、每次计数时钟数、模式、目标、误差、验证方式、工具和量规。当前定时目标按“单次溢出间隔”定义；完整输出周期应先换算。不完整配置只允许定性排查，不能下发数值结论或评分。
5. 学生提交现象和代码后进入待审；教师对照原提交、模型初稿和最后保存的复核稿，保存或下发。过期版本的保存、发布和回执会被拒绝。
6. 学生提交观察或修改代码。基础、综合、拓展依次由教师核验；“卡住”只请求帮助，不越级。没有编译、实测依据时不能认定运行正确。新一轮继续使用同一单号，保留此前发布和尝试记录。
7. 教师核对学习卡有效状态、参与人数，再确认统计分母。完成率＝教师确认完成的有效学习编号数÷有效参与编号数。未确认分母时不显示完成率；没有测评依据不提供掌握率。

实际班级规模、硬件参数、评分量规、部署位置和学院审查形式需由任课教师补齐。演示参数、接口测试和模型输出不能替代真实课堂成效。

## 演示和模型故障

```bash
npm run demo:classroom
npm run demo:constraint
```

`demo:classroom` 在已有教师下建立明确标识的演示班级、三类待人工复核样例及匿名学习卡；参数默认未确认，不调用外部模型。演示学生凭据写入 `tmp/demo-student-access.txt`。重复运行不会重复创建演示班级。旧 `demo:diagnose` 改为此安全演示入口；旧自动复核脚本已停用，发布统一经过教师工作台。

模型密钥只从环境读取。当前接入适配器支持千帆、星火和 GLM；供应商、模型版本、数据处理条件及学校许可应在正式试用前确认，选择某家供应商不等于已完成合规审查。未配置密钥、模型超时或输出不合格时，提交保留为“待人工处理”。单次模型请求上限 40 秒、总预算 90 秒，最多尝试两次；同时最多 4 个生成请求，超过容量的提交保留并转人工。模型重试不重复创建诊疗单。

自动脱敏覆盖常见姓名自述、英文署名、联系方式和学号，但不保证识别所有身份信息。学生应在提交前删除身份信息；平台保存脱敏后的内容和规则命中项。密钥不进入诊疗记录或导出。

## 版本与数据口径

- 教师会话、班级归属和学习主体在服务端校验；所有审核、统计及导出要求教师身份与本班权限。
- 诊疗保存提示词版本、图谱版本、实验配置、量规、发布版本、任务尝试和事件时间。复核历史追加保留，学生读取批准版本。
- 数据来源区分 `classroom`（课堂）、`demo`（演示）、`test`（测试）、`legacy_unknown`（历史待核实）。历史和演示不纳入真实课堂统计。
- 周报按事件实际发生时间统计；完成事件按匿名学习主体去重。重复下发不重复计算首次反馈时间。案例包含实际发布指导、前后代码及验证记录；缺失效果或反馈保留“未记录”。
- 图谱含 279 个节点、202 条真实先修边；界面只绘制所选子图中实际存在的边，不按排列补线。图谱来源保持只读。
- 定时和波特率由程序计算。11.0592 MHz、12 个时钟/计数、50 ms 的 16 位初值为 `0x4C00`；12 MHz 同条件为 `0x3CB0`。计算忽略软件开销，仍须教师实测验证。

## 迁移、备份与恢复

`npm run db:migrate` 自动识别旧结构、用 SQLite 在线备份保存 `tmp/backup-*.db（首次原库备份另有 pre-upgrade 前缀）`，执行版本迁移并校验旧字段内容、数据库完整性及外键。旧记录默认归为历史待核实；原文、旧复核稿和关联关系保留。不要在现有数据上用 `prisma db push` 代替迁移。

另行备份：使用 SQLite `.backup` 命令生成一致副本，妥善保存到受控位置。恢复时先停止平台，保留当前数据库副本，将备份恢复到目标 SQLite 文件，再运行迁移和完整性检查，验证教师登录、原记录及复核稿。备份和恢复演练应在独立副本进行。

npm run build                 # 生产构建

## 汇编调试与原始材料（2026-09-25）

学生登录后，在八个实验任一指导页展开“真实汇编与虚拟调试”，可编辑教学摘录，使用 AS31 汇编为 Intel HEX，再由 SDCC 的 ucSim/s51 执行机器码。页面显示程序计数器、寄存器、RAM、端口电平与累计模拟时间，并从同一次执行中对端口电平作最多64点采样；支持单条及批量推进、实验四的 P3.2/INT0 按键输入和 HEX 下载。采样可能漏掉窄脉冲，实验八显示的高电平占比只是所选指令窗口中的采样估计。修改源码或晶振后须重新编译。先前从“芯智育才”移植的 TypeScript 内核只保留为测试参考，学生界面的结果不再取自该内核。实验三的示例按 12 MHz、经典 12T、10 ms 初值、100 次溢出后翻转 P0.0 编写，目标是完整周期约 2 s；软件开销使实际模拟周期略有偏差，不能把理想初值直接当成实测值。

运行环境需安装 SDCC（提供 `s51`）和 AS31。本机验证组合为 SDCC 4.6.0_1、s51 0.9.9 与 AS31 上游固定提交 `53f1a78a1f262a67e1a388c20ec7e8357ac30eaa`。macOS 可先执行 `brew install sdcc`，再运行 `bash scripts/setup-8051-tools.sh`；脚本从上游拉取 AS31 并修正其在 64 位系统上的位移常量，构建到用户目录，不把第三方源码或二进制提交进仓库。其他系统可设置 `VE_AS31_PATH`、`VE_S51_PATH` 指向相应可执行文件。运行 `npm run test:native` 会对八个示例、历史六份源码、10/20 ms 定时和 INT0 输入做实际汇编/仿真检查。当前公网是经 Cloudflare Tunnel 访问本机 Node 服务，因此这些外部工具须在运行该服务的主机上安装；若以后改为独立云主机，需在该主机重新配置。

八个实验均可编译、执行并查看指令状态。实验二可切换2025年分组灯程序，实验三可切换备课的20 ms×50程序；实验五默认运行校正版八位0–7扫描，P0段码和P1位选在同一采样时刻解码，扫描间隔由50次T0溢出逐步减至1次。原版 `xm2.asm` 另列为故障对照：它把10个位次用于仅8项的查表，后两位越界。实验六默认运行备课双音程序，可比较P2.0两段翻转节奏。实验七默认运行由历史时钟扩展的“八位显示＋分钟报警”，显示和P2.0报警均由实际执行结果采样；历史原程序从 `S71.lst` 恢复，重新汇编的183字节机器码与留存 `S7.hex` 逐地址一致。实验八可切换30%/70%控制脚PWM与八状态抽象步进相序。生成的校正版、报警与相序程序均明确标出，不冒充原始实验源码。

这些结果证明8051机器码和**虚拟数字控制信号**可运行、可调试，不等同于本班板卡已接通并完成实物实验。s51没有在此平台内接入数码管光学效果、蜂鸣器声学模型、电机驱动与机械响应；图上的采样也可能漏掉窄脉冲。实验四的实际按键消抖、实验八的驱动型号及引脚映射仍须用本班器材核对。当前公网通过 Cloudflare Tunnel 连接本机服务，不能当作独立云主机或脱离本机运行的部署。

历史备课 `.ASM` 原件的六份编码转存见 `assets/assembly-source/`，在教师资料库以**未发布候选资料**保存；教师须先核对源程序、芯片和接线，再选择是否发布。实验四历史候选程序走 INT1/P3.3，与报告 INT0/P3.2 不符，平台调试示例另按报告写为 INT0。普中-6 V1.2 手册第 3.1 节的开发板实物照片作为型号识别参考展示，**不是本班现场照片**。八实验报告、教师 PPT、历史程序、手册照片和生成教学示例的关系见 `docs/project-deliverables-map.md`。

远程入口 [ve.sunyancai.top](https://ve.sunyancai.top/) 已通过 Cloudflare Tunnel 使用 `ve.sunyancai.top` 专属路由。该域名在有互联网连接的校内网络也可访问；不能据此推断断网内网可用。当前生产进程仅监听本机回环地址；若学校要求纯内网、无需互联网的访问，需由校内 DNS/网关和部署位置另行确认，不应改动现有 `.top` 其他站点路由。
